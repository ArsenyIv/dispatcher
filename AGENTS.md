# Инструкция агенту для работы в этом репозитории

Проект: экран диспетчера (Vue 3, TypeScript, Pinia). Экран открыт всю смену, поэтому корректность данных и стабильность важнее скорости разработки. Перед началом прочитай [DESIGN.md](DESIGN.md).

## 1. Команды

Менеджер пакетов: **pnpm** (не npm и не yarn). Установка: `pnpm install`. `make` вызывает те же скрипты: `pnpm run <имя>`.

| Команда | Что делает |
| --- | --- |
| `make mock` | Заглушка сервера. Параметры окружения: `PORT`, `LOAD`, `FAULTS`, `ROLE` |
| `make dev` | Экран в режиме разработки (прокси на заглушку; адрес можно задать через `MOCK_URL`) |
| `make check` | Типы (`vue-tsc`), ESLint, `dependency-cruiser`, `tools/checkMutators.mjs`. Любое нарушение — ошибка |
| `make test` | Модульные тесты (Vitest) |
| `make e2e`, `make perf` | Пока не реализованы. Не заявляй, что они проходят |

Перед тем как считать задачу выполненной, запусти `make check` и `make test`. Если менялись `sync`, `commands`, `fleet` или `map`, дополнительно проверь экран вручную на заглушке со сбоями (`FAULTS=drop,dup,reorder`, `FAULTS=slow`, `FAULTS=reset`). Не заявляй, что проверки прошли, если ты их не запускал.

## 2. Структура

Код лежит в `src/modules/<имя>`. Внутри модуля: `index.ts` (единственная публичная точка), `api`, `helpers` (бизнес-логика), `utils` (технические функции), `store`, `containers`, `components`. Сборка (приёмник сообщений, запуск) находится в `src/app`.

Модули: `contract` (типы и проверка формы сообщений), `platform` (HTTP-клиент, часы, ключи, форматирование времени), `session`, `sync` (движок синхронизации), `fleet` (машины и пункты), `decisions`, `commands`, `map`, `queues`. Владельцы состояния перечислены в DESIGN.md. Не создавай второго владельца для того же состояния.

## 3. Правила кода и чем они проверяются

1. Модули импортируют друг друга только через `index.ts` владельца, циклов нет. Проверка: `.dependency-cruiser.cjs`.
2. Контейнер (`*Container.vue`) отвечает за запросы, состояние и ошибки. Компонент показывает `props` и сообщает о действиях через `emit`; запросов не делает, store не использует. Проверка: `dependency-cruiser` и правила ESLint для `src/modules/*/components`.
3. HTTP и WebSocket только в слое `api` через единый клиент из модуля `platform`. Запрещены `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource` и сторонние HTTP-клиенты вне `api`. Проверка: `no-restricted-globals`, `no-restricted-properties`, `no-restricted-imports` (`eslint.config.ts`).
4. Pinia только для общего долгоживущего состояния. Функция, меняющая состояние store, называется с суффиксом `Mutator`. Проверка: `tools/checkMutators.mjs`.

Если проверка мешает, измени код, а не конфигурацию проверки. Не отключай правила, не добавляй исключения, не используй `eslint-disable` и `@ts-ignore` (они запрещены самими проверками). Если считаешь, что правило нужно изменить, остановись и спроси человека.

## 4. Инварианты, которые нельзя нарушать

1. **Сервер — единственный источник истины.** Очередь, ожидание, выигрыш и любые показатели экран не считает, а показывает как пришли (разрешено только форматирование). Оптимистичных обновлений нет: после команды на экране состояние из ответа сервера.
2. **Порядок сообщений.** Сообщения применяются строго по `seq`. Дубликат (`seq` не больше последнего применённого) отбрасывается. Пропуск ведёт к переподключению с `since`, `reset` ведёт к новому снимку. Не меняй логику `sync` без теста на изменённый случай.
3. **Версии.** Объект применяется, только если его `version` не меньше хранимой (`mergeByVersion`).
4. **Идемпотентность.** У команды один `Idempotency-Key` и одна версия `If-Match` на всё намерение, включая повторы. Повторять можно только ошибки сети, таймаут и 5xx.
5. **Время.** Время сервера берётся из heartbeat и снимка плюс `performance.now`. Часы браузера не используются. Время показывается в поясе площадки из `/api/me`, а не в поясе браузера.
6. **Машины** хранятся вне реактивности Vue (`VehicleRegistry`) и рисуются на Canvas. Не клади машины в `ref`, `reactive` или Pinia.
7. **Никаких внешних адресов**: шрифты, иконки и графика только внутри сборки.
8. **Память.** Все структуры, растущие со временем, ограничены по размеру. Таймеры, слушатели и подписки снимаются при размонтировании.
9. **Роли.** Кнопки действий скрыты у наблюдателя, но ответ 403 обрабатывается всегда.
10. **Текст с сервера** (например, причина решения) выводится только как текст: `v-html` не используется.

## 5. Запреты

1. Не добавляй зависимости без разрешения человека.
2. Не изменяй заглушку сервера, чтобы заставить тест пройти, и не меняй ожидания тестов под результат кода.
3. Не удаляй и не ослабляй тесты и проверки.
4. Не выдумывай поля API: источник — модуль `contract`.
5. Не оставляй `TODO` без записи в README и отладочный вывод в коде. Объект `window.__dispatcher` существует только в режиме разработки и только для проверок; не используй его в коде приложения.
6. Не делай масштабных рефакторингов вне задачи.

## 6. Как работать

1. Перед изменением прочитай модуль и его `index.ts`. Меняй минимум файлов.
2. Для ошибок сначала напиши тест, который воспроизводит ошибку, потом исправляй.
3. Один запрос на изменение решает одну задачу. Если задача затрагивает несколько модулей, предложи план и дождись подтверждения человека.
4. В конце сообщи: что изменено, какие команды запущены и с каким результатом, что не проверено, какие допущения сделаны.
5. Если требование неясно или противоречит этому файлу, задай вопрос, а не угадывай.
